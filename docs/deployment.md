# Публікація та синхронізація

Адміністрування, зовнішній LLM, міграція та актуальні перевірки від 2026-10-02 описані окремо в [admin-llm.md](admin-llm.md).

## Поточне розгортання

Станом на 2026-10-01 сайт підключено до проєкту JobSearch у Supabase Free, Canada (Central). Міграцію застосовано через SQL Editor; точну адресу GitHub Pages збережено як Site URL і єдиний дозволений Redirect URL. Публічні параметри задані у GitHub Actions variables, секретні ключі у збірку не входять. Email/Password увімкнено з підтвердженням адреси; анонімний вхід вимкнено.

Перевірено у живій базі: збереження власного рядка, збільшення версії, відмова при застарілій версії, ізоляція двох акаунтів, заборона анонімного читання й запису. [Відтворюваний SQL-тест](../supabase/verify_workspace.sql) використовує синтетичні записи й завершується відкатом транзакції. Окремо публічний HTTP API відхилив анонімне читання таблиці та виклик функції збереження.

2026-10-02 підтверджено особистий вхід і живий обмін налаштуваннями через Supabase між двома заздалегідь відкритими вкладками Chrome: зміна на першій з'явилася на другій після хмарного оновлення, а відновлення початкового значення на другій — на першій. Тестові зміни скасовано. Це перевірка двох відкритих інтерфейсів одного акаунта; окремий фізичний телефон ще не перевірявся.

Для першого запуску використайте email учасника вашої організації Supabase: стандартна доставка надсилає листи лише учасникам команди й має суворі обмеження. Для інших адрес потрібен власний SMTP або створення підтвердженого користувача власником через Dashboard. [Офіційні обмеження пошти](https://supabase.com/docs/guides/auth/auth-smtp).

## Архітектура першої версії

- **GitHub Pages** публікує інтерфейс і коротку вибірку публічних вакансій. Особистих даних у збірці немає.
- **Supabase Free** зберігає приватний простір після входу: профіль, обрані вакансії, заявки та тексти документів. Один акаунт відкриває той самий простір на різних пристроях.
- **Браузер** зберігає локальну копію, щоб не втрачати зміни при перебоях. Резервну копію можна завантажити у налаштуваннях.
- **GitHub Actions** отримує обмежену стрічку Job Bank під час публікації та двічі на добу. Запуски за розкладом можуть затримуватися. Саме успішне отримання, а не розклад, визначає дату оновлення на сайті.

Станом на 2026-10-01 GitHub Pages доступний безкоштовно для публічних репозиторіїв. Supabase Free надає 500 МБ бази даних і може призупиняти проєкт після тижня неактивності. Для цього сервісу не потрібні платний тариф, домен або API штучного інтелекту. Безкоштовний тариф не гарантує безперервної роботи; актуальні ліміти перевіряйте у провайдера.

Джерела: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [Supabase Free](https://supabase.com/pricing).

## Підключення Supabase власником

1. Створіть проєкт у безкоштовній організації Supabase. За можливості виберіть канадський регіон. Збережіть пароль бази приватно; він не потрібен браузеру.
2. Застосуйте [міграцію](../supabase/migrations/202610010001_workspace.sql) у SQL Editor або через Supabase CLI. Вона створює таблицю з доступом лише до власного рядка та функцію збереження з перевіркою версії.
3. У Authentication → URL Configuration задайте Site URL і дозволений Redirect URL: `https://dolzhenkovital.github.io/JobSearch/`.
4. Залиште Email/Password authentication увімкненим. Налаштуйте підтвердження адреси й доставку листів відповідно до вашого провайдера. Стандартна пошта Supabase має обмеження; для особистого запуску можна створити підтверджений акаунт у Dashboard → Authentication → Users. Пароль має задавати власник акаунта приватно. Не публікуйте пароль у Git або чаті.
5. У GitHub → Settings → Secrets and variables → Actions → Variables додайте `VITE_SUPABASE_URL` і `VITE_SUPABASE_PUBLISHABLE_KEY`. Це URL проєкту та **публічний publishable/anon key**. Не використовуйте `service_role`, secret key, management token або пароль бази.
6. Запустіть workflow **Deploy** (він публікує прод і stage разом; див. [ci-cd.md](ci-cd.md)). Після публікації вікно Налаштування → Синхронізація покаже форму входу.
7. Перевірте вхід на двох пристроях: збережіть тестову вакансію на першому, відкрийте другий і перевірте її появу. Перевірте, що інший акаунт не бачить цих даних. Код без успішного тесту двох сесій не означає перевірену живу синхронізацію.

Якщо підключення ще не виконане, сайт прямо показує цей стан і працює локально. Не вводьте приватні дані до тестового або чужого Supabase-проєкту.

## Як працюють зміни між пристроями

Зміни зберігаються локально одразу; хмарне збереження виконується після короткої паузи. Перевірка віддалених змін виконується при поверненні до вкладки, відновленні мережі та періодично, поки сторінка відкрита. Запис містить номер версії. Якщо обидва пристрої редагували різні копії, сайт не перезаписує їх мовчки: пропонує вибрати версію та зберігає локальну копію перед вибором. Додатково можна завантажити JSON-файл.

Відкрита форма налаштувань відображає отримані хмарні зміни в полях, які користувач не редагував. Незбережені зміни залишаються у формі; збереження застосовує лише відредаговані поля до поточного простору, а не повертає стару копію всіх налаштувань. При зміні акаунта чернетка налаштувань очищається.

Гостьовий простір і простір акаунта мають окремі локальні копії. Новий порожній акаунт може прийняти гостьові дані; існуючий хмарний простір завантажується після входу. Не залишайте відкритий акаунт на спільному пристрої.

## Локальний запуск

```text
npm ci
python scripts/collect_jobbank.py
npm run dev
```

Для локальної синхронізації скопіюйте `.env.example` у `.env.local` і задайте тільки публічні параметри проєкту. Відкрийте адресу з `/JobSearch/`, яку покаже Vite.

Перевірки:

```text
npm run lint
npm run typecheck
npm test
python -m unittest discover -s scripts -p "test_*.py"
npm run build
npm run test:smoke
```

Зміни потрапляють у прод через гілку `stage`; обов'язкові перевірки, код-рев'ю та тестове середовище описані в [ci-cd.md](ci-cd.md).

## Межі поточної версії

- Job Bank повертає обмежену вибірку коротких записів, а не всі вакансії Канади. Повний опис додається користувачем. Зникнення зі стрічки не означає закриття.
- Indeed і Jobillico відкривають зовнішній пошук; автоматичні інтеграції з їхніми акаунтами не підключені.
- Збіги навичок — буквальні текстові підказки, а не професійна оцінка чи прогноз найму.
- Пакет документів починається з вихідного CV й базового листа. AI-запит можна скопіювати та використати у власному помічнику; автоматичних платних викликів немає.
- DOCX експортується з простим оформленням. PDF зберігається через системне вікно друку. Готові документи потрібно перевірити перед поданням.
- Жодні заявки або повідомлення роботодавцям не надсилаються автоматично.
