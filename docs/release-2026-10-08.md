# Перевірка релізу 2026-10-08

Це датований журнал перевірок перед перенесенням `stage` у `main`, а не автоматична гарантія поточного стану. Після публікації звіряйте `version.json` з комітом і запуском Deploy. GitHub Pages не застосовує міграції Supabase і не розгортає Edge Function.

## Stage

Базовий перевірений інтерфейс: `cb4e6640ad5e5f6480a8407390bf8df378c5f773`, Deploy `37829799960`. Окремі міграції, `jobsearch-api` і Before User Created hook застосовані вручну.

- Лімітований промокод витратив одну активацію при створенні акаунта до підтвердження email; наступна реєстрація отримала `promo_code_inactive`.
- Перекриття SQL-транзакцій для останньої активації дозволило лише одного користувача. Це не тест одночасних HTTP-запитів.
- Дві реєстрації з необмеженим кодом через налаштований Brevo SMTP доставили листи. Лічильник дорівнював 2 до підтвердження email; один акаунт підтверджено, роль звичайного користувача та ізоляцію простору перевірено. Вимкнений код відхиляє реєстрацію.
- Лист відновлення доставлено, відкриває форму нового пароля. Сам пароль не змінювали.
- Два справжні AI-запити успішні, сумарно 3123 токени. Тестовий простір повернено до порожнього стану; всі QA-промокоди вимкнені.

## Production перед публікацією інтерфейсу

Міграцію реєстрації, поточну `jobsearch-api` та hook застосовано вручну. Перевірки володіння простором, конфлікту ревізій, заборони анонімного доступу та правил реєстрації пройшли в hosted Supabase. Синтетичні SQL-перевірки реєстрації відкочено. Публічне читання режиму повертає HTTP 200, виклик Edge Function без авторизації — HTTP 401.

До публікації нового інтерфейсу з полем промокоду production тимчасово залишено в режимі вільної реєстрації. Під час випуску потрібно встановити режим лише за промокодом, як погоджено з власником.

Власник приватно ввів OpenAI та SMTP ключі. SMTP збережено й перевірено після перезавантаження: Brevo, порт 587; пароль прихований. Наявність AI-ключа підтверджено без читання його значення. Провайдер: OpenAI Responses API, `gpt-6-luna`, effort `medium`.

Створено ізольований синтетичний QA-акаунт. Лист підтвердження доставлено та посилання успішно підтвердило акаунт. Лист відновлення доставлено й відкрив форму нового пароля; зміну пароля не виконували. Тестовий акаунт не має ролі адміністратора.

## Виправлення і межі

Форма акаунта тепер очищує email, пароль, промокод і повідомлення після зміни акаунта або конфігурації підключення. Запізніла відповідь попередньої форми ігнорується. Додано три регресійні тести, включно із захистом від повторного надсилання.

Якщо мутація реєстрації успішна, але перечитування стану неуспішне, панель повідомляє про збережену зміну та прибирає дії зі старими ревізіями до успішного оновлення. Окремий регресійний тест перевіряє цей випадок. Повторна перевірка режиму після auth-помилки також ігнорує відповідь після розмонтування форми.

Локально пройшли lint, перевірка типів, 130 unit-тестів, 3 Python-тести колектора, build і 10 desktop/mobile smoke-тестів. Перед злиттям потрібні всі обов'язкові перевірки актуального коміту PR; після публікації — збіг маркера, живий інтерфейс і режим реєстрації.

Не виконували навантажувальний тест на тисячі користувачів, перевірку фізичного телефону, експорт DOCX/PDF чи надсилання заявки роботодавцю. Власний домен і автентифікований домен відправника ще не підключені.

## Доповнення 2026-10-09 перед промоцією

Адміністративні мутації додатково захищено синхронним блокуванням повторного запиту. Після будь-якої помилки мутації панель вимагає перечитати стан: втрачена HTTP-відповідь могла приховувати вже збережену зміну. Регресійний тест перевіряє подвійне надсилання, неоднозначну відповідь, оновлення та зняття блокування. Серверна міграція вже застосована в обох середовищах, включно з `registration_user_codes`; deployment skew не підміняється успішним порожнім результатом.

Оновлення списку та мутації використовують спільне синхронне блокування, включно з початковим завантаженням. Тест перевіряє обидва порядки спроби паралельних дій та використання нової серверної ревізії після оновлення.

Повторна локальна перевірка: lint, typecheck, 132 unit-тести, 3 Python-тести, build і всі 10 desktop/mobile smoke-тестів успішні.
